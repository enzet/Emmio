# Emmio iOS

A native iOS client for Emmio, sharing the FastAPI backend in
[`emmio/api/app.py`](../emmio/api/app.py) with the web frontend: log in, pick a
course, and run a **spaced-repetition learning session** with all four question
types the server serves.

## Layout

```
ios/
├── project.yml        XcodeGen spec → generates Emmio.xcodeproj (git-ignored)
├── run.sh             generate + build + launch in the Simulator
├── EmmioKit/          Swift package: API client + models (no UI, unit-tested)
│   ├── Package.swift
│   ├── Sources/EmmioKit/
│   │   ├── Models.swift        Codable mirrors of the API's JSON
│   │   ├── HTMLText.swift      HTML translation fragment → plain text
│   │   ├── Grading.swift       typed-answer acceptance rule
│   │   └── EmmioClient.swift   async actor over the API routes
│   └── Tests/EmmioKitTests/    XCTest suite (request shape, decoding, grading)
└── EmmioApp/          SwiftUI app source (depends on EmmioKit)
    ├── EmmioApp.swift          @main + auth gate
    ├── AppModel.swift          token/server persistence, auth state
    ├── LoginView.swift
    ├── CourseListView.swift
    └── LearnView.swift         the learning session (four question types)
```

The split is deliberate: `EmmioKit` is pure Foundation, so all networking and
parsing logic is testable with `swift test`, while `EmmioApp` stays a thin
SwiftUI shell. Requires **iOS 17+** (uses `ContentUnavailableView`).

## The learning loop

Driven by `GET /api/v1/me/courses/{id}/question`, which chooses the type
server-side and returns its grading key. The client renders the matching card,
grades the answer client-side (mirroring `web/app.js`), and records it:

| Type | Card | Grading | Recorded |
|---|---|---|---|
| `know` | Show word → self-assess → reveal meaning | none (self-assessed) | `y`/`n` |
| `choice` | Pick the translation | picked `== answer` | `y`/`n` |
| `type_word` | Read meaning (word blanked), type it | exact match in `accepted` | `y` typed / `n` gave up / `s` skip |
| `connect` | Match words ↔ translations | per pair | `y`, or `n` if that word had a wrong attempt |

Supporting routes: `.../translation?hide_word=…` for the revealed meaning /
typed-recall prompt, `.../answer` (carries `question_type` + `seconds`), and
`.../undo` (re-presents the freed word as a `type_word` card). A `type == null`
question ends the session.

## Running it

**Backend** (from the repo root):

```sh
uvicorn emmio.api.app:app --reload
```

That serves the API on `http://localhost:8000`. Create a course in the web app
first (`/app/courses`) — this iOS version reviews existing courses but does not
create them or add new words yet.

The default server URL is `http://localhost:8000`, editable on the login screen;
the simulator shares your Mac's network, so localhost just works. (For a
physical device, enter your Mac's LAN IP, e.g. `http://192.168.x.x:8000`; the
`NSAllowsLocalNetworking` ATS exception in `Info.plist` permits plain HTTP to
local hosts.)

## Building & running the app

The `.xcodeproj` is generated by **XcodeGen** from `project.yml` (and
git-ignored), so it never causes merge conflicts. Regenerate it after adding or
removing source files:

```sh
cd ios && xcodegen generate      # writes Emmio.xcodeproj
open ios/Emmio.xcodeproj          # then build/run with ⌘R
```

Or do the whole generate → build → boot-simulator → install → launch loop from
the command line:

```sh
cd ios && ./run.sh                # override with SIMULATOR="iPhone 17 Pro" ./run.sh
```

Prerequisites: Xcode with the iOS platform + a simulator runtime installed
(Xcode ▸ Settings ▸ Components, or `xcodebuild -downloadPlatform iOS`), and
`xcodegen` (`brew install xcodegen`).

## Verifying the core

```sh
cd ios/EmmioKit && swift test     # builds EmmioKit and runs the unit tests
```
